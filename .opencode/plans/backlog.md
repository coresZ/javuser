## 文件名清单导入同步（番号/标题回填 + 状态候选 · 库为权威）

**状态**：待开发

### 背景与决策
- 用户本地视频文件靠「文件名追加标记」记录状态，但标记形式多变（什么样的都有），与脚本库（GM 存储）产生**分歧**
- **权威方向**：脚本库为准（标准化账本）；本地文件是人工视图，格式不可靠，不反向作为权威
- 文件名中**可靠信息 = 番号 + 标题**；状态标记仅作候选提示，不自动覆盖
- 同步通道：**粘贴文件名清单**（油猴沙箱读不了本地磁盘，须经文本传输）

### 方案要点
**1. 解析层（启发式容错）**
- 番号提取：正则 `[A-Za-z]{2,}-\d{2,}`，兼容变体（`-C/-UC/-CH/_HD`、`.`/`_`/`-` 分隔、小写）→ 归一化大写标准番号
- 标题提取：番号之后到扩展名之前的文字，剥离常见 tag（分辨率/片源/字幕）→ 拟标题
- 状态启发：`已看/看过/seen/watched` → 已看候选；`关注/收藏/fav` → 关注候选（仅提示）

**2. 匹配层**：按归一化番号 `getItem`，产出四类
| 结果 | 含义 | 动作 |
|---|---|---|
| 匹配到 | 库已有 | 标题为空 → 回填 |
| 库中缺失 | 本地有、库无 | 一键新增（含标题） |
| 清单缺失 | 库有、本地未列 | 提示（可能已改名/删除） |
| 状态候选 | 文件标记与库冲突 | 高亮，人工勾选 |

**3. 决策层（向导式 diff）**
- 标题回填：默认自动应用（安全，顺带解决「有的没标题」）
- 新增番号：一键加入，备注标注来源「文件名」
- 状态候选：逐条勾选确认，走现有 `markItem`
- 汇总：`新增 N · 标题回填 M · 已看候选 K`；存储 schema 不变

### 入口
Header `⋯` 菜单加「导入文件名」→ 粘贴多行文件名 → diff 向导。

### 明确不做
- 不自动重命名本地文件（浏览器无权限；用户命名多变）
- 不做「文件覆盖库」状态（脏标记不能当权威）
- 不强制统一命名约定

### 后续可选增强
- 反向「建议重命名清单」生成（库状态 → 建议文件名），由本地工具 / 手动执行

### 验收思路
- 粘贴含变体 / 脏标记 / 真实标题的样例清单 → 番号与标题提取正确
- 标题回填、新增入库、状态候选勾选应用均正确落库
- 库状态不被文件名脏标记覆盖；`node --check` 通过
